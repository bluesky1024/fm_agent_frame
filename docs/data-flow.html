端到端数据流 · 一次完整对话的生命周期

用户发起 → 前台（当前 CLI / 未来 HTTP）→ Agent 编排 → LLM + 工具 + 记忆 → 结果回传呈现

—— 实线 = 请求 / 调用 - - 虚线 = 返回 / 回填 红色框 = ReAct 循环
要点：
① 第 1 轮 LLM 调用不一定给答案，而是返回「要调哪个工具 + 参数」；Agent 执行工具后，把结果作为 ToolMessage 回填，进入下一轮。
② 第 2 轮起 LLM 能「看到」上一步工具结果，据此决定继续调工具、还是给出最终文本——这就是 ReAct（Reasoning + Acting）的循环。
③ 循环受 max_steps=8 约束，防止死循环。
④ 当前「前台 / 入口」是 CLI（examples/02_tool_agent.py 里的 print）；未来换成 server（FastAPI）时，只有最左、最右两段变（HTTP 请求/响应），中间 Agent 编排完全不变——这正是分层解耦的好处。
