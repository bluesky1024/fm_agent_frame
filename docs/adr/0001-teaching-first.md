# ADR-0001：教学优先，而非生产完备

- 状态：已接受
- 日期：2026-10-17
- 决策者：仓库所有者 + Claude

## 背景

本仓库的定位是学习 LLM Agent 的入口，需要覆盖标准 Agent 的完整模块，但允许复杂模块只预留接口。架构调整可以按"教学清晰"或"工业可用"两套标准评价，二者的目录结构、抽象层次和实现深度不同。

## 决策

以**教学优先**为第一原则：

- 每个模块有清晰协议与单一职责，能被单独阅读、单独替换。
- 复杂能力（长期记忆、检索、多 Agent、评测、MCP、沙箱）优先保证接口完备和链路接线，实现做到最小可运行即可。
- 流式、重试、并发、容错等生产细节放在实现层或协议参数中，不污染主线叙事。
- 不追求多租户、分布式、多供应商矩阵等生产特性。

## 后果

正面：

- 学习者能从 `core → llm/tools → runtime → context → capabilities` 逐层理解，不被工程细节淹没。
- 最小实现 + 完整接口的组合，让每个模块都在真实流程中可见，而不是死代码。

负面：

- 框架不直接适用于生产；最小实现可能在极端输入下不稳定。
- 后续若转为生产用途，需要补齐重试、限流、沙箱等能力。

## 替代方案

- **生产可用优先**：模块需要大量容错与并发设计，学习主线会被稀释，未采用。
- **纯接口文档、不接线**：接口会与真实流程脱节，学习价值低，未采用。
