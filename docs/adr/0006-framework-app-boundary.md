# ADR-0006：框架与应用的边界

- 状态：已接受
- 日期：2026-10-17
- 决策者：仓库所有者 + Claude

## 背景

现状中 `src/agent_frame/desktop/` 同时包含通用截屏/鼠标/观察/标注与扫雷棋盘几何，`src/agent_frame/tools/desktop/` 包含点击格子、插旗、重开游戏等应用工具。框架包因此与具体游戏耦合，并产生循环导入。

## 决策

- **通用计算机使用能力**（截屏、鼠标、Observer、标注）保留在框架内，路径为 `capabilities/computer_use/`。
- **扫雷应用**（棋盘几何、点击/插旗/重开工具、提示词、启动逻辑）迁移到 `apps/minesweeper/`。
- `games/minesweeper.py` 作为被操作的目标程序保持不变。
- 框架包禁止 import `apps/`；应用通过框架公开 API 组装 Runtime、Spec 与工具。

## 后果

正面：

- 框架可复用到其他桌面任务，不再绑定扫雷。
- 消除 `desktop ↔ tools/desktop` 循环依赖。
- 应用代码可以自由演进，不影响框架依赖规则。

负面：

- 迁移期间扫雷功能暂时不可用（已确认接受，P4 恢复）。
- 需要新增应用级配置与启动入口。

## 替代方案

- **保留扫雷在框架内**：继续污染框架边界，未采用。
- **把所有桌面能力都移出框架**：通用能力失去教学价值，未采用。
