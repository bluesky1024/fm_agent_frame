# ADR-0004：上下文装配与记忆存储分离

- 状态：已接受
- 日期：2026-10-17
- 决策者：仓库所有者 + Claude

## 背景

现状中每轮循环直接把 system prompt 拼进消息并写入历史（`agent/tool_use.py:55-58,96`），导致 system 消息重复累积；工具轮中 assistant 的文本内容被丢弃（`:75`）；"给模型看什么"和"记住什么"混在一起，压缩与召回无处安放。

## 决策

- 新增 `context/` 层：`ContextBuilder` 每轮组装 **system prompt + 压缩后的持久历史 + 记忆召回 + 检索片段**。
- 装配结果是**临时请求视图**，不写回持久历史。
- `memory/` 只负责持久历史与长期记忆的存取，不负责拼装提示词。
- `ContextProvider` 协议允许记忆召回、检索、画像等贡献上下文片段。
- 压缩策略由 `context/compaction.py` 管理，首版实现摘要 + 滑动窗口。

## 后果

正面：

- 修复 system 重复注入与 assistant 文本丢失两个 bug。
- token 预算、压缩、召回有明确归属，便于教学和替换。
- 装配可独立测试，不依赖真实 LLM。

负面：

- 多一层 `context` 概念；装配与存储的边界需要文档持续维护。
- 摘要压缩需要额外 LLM 调用，需在配置中显式开启并计入用量。

## 替代方案

- **在 memory 内部拼装提示词**：职责混杂，压缩与召回无法复用，未采用。
- **每轮重建完整历史**：简单但 token 成本高，无法支持长会话，未采用。
