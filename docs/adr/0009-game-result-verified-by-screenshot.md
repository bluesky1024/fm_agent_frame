# 胜负由截图校验，模型结论只作停止信号

- 状态：已接受
- 日期：2026-10-17
- 决策者：仓库所有者 + Claude

实际运行中，模型在只剩 2 个安全格未翻开（已翻开 76/78）时仍输出「本局结束：胜利」。如果应用层信任这段文本，就会在棋局尚未结束时退出。决定：模型仍只能「调用工具」或「输出固定结束结论」，但 `run_autoplay` 在每次运行结束后直接读取最新截图统计棋盘状态；只有「已翻开格数 == 总格数 - 雷数」才判定胜利，只有盘面出现红色 `*` 才判定失败。模型结论只作为停止操作的信号，不直接决定退出。

## 考虑过的方案

- **完全信任模型文本**：已发生误报，未采用。
- **新增 `finish_game` 工具**：同样依赖模型判断，只是换了载体，未采用。
- **修改目标游戏暴露状态**：破坏「视觉 agent 操作黑盒目标程序」的演示定位，未采用。

## 后果

- `apps/minesweeper/board_state.py` 依赖目标游戏的固定配色（`#bbbbbb` / `#e0e0e0` / `#cccccc` / 红色 `*`），更换游戏或改配色时需同步更新。
- 观察 caption 直接给出雷数、已翻开、未翻开与插旗数，模型可自行核对；误报胜利时应用层追加提示并继续操作。
- 同一批工具调用中的鼠标动作必须串行执行（Shift 与普通点击交错会丢失或变成插旗），见 `MouseController` 的锁。
